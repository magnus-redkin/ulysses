# Gryphon: сервис управления гейтами (gryphon guardian gateways)

## Основные принципы
    Отдельный процесс (systemd-юнит), написан на Python, работает в асинхронном цикле.
    Не зависит от бэкенда, но может использовать его API для алертов и, опционально, для логирования.
    Хранит своё состояние (пул IP, текущие назначения) в JSON-файлах, без отдельной БД.
    Интегрируется с существующей инфраструктурой через:
        config/gate_ips.json — читает и обновляет (этот же файл используют монитор и HFM).
        SSH к гейтам и HFM (ключи уже есть).
        API хостинг-провайдеров для управления IP.
    Все операции логируются, важные события отправляются админу через Telegram.

## Что делает Gryphon
    Постоянно (но легковесно) следит за здоровьем гейтов.
        Использует тот же механизм, что и монитор: запускает по SSH на HFM скрипт monitor.sh с ожидаемыми IP, анализирует вывод.
        Проверяет не только SOCKS5-ответ, но и соответствие внешнего IP ожидаемому.
        Чтобы исключить ложные срабатывания, требуется N последовательных неудач (например, 3 проверки с интервалом 30 секунд). Только после этого считается, что гейт «упал».
    При подтверждённом отказе гейта запускает процедуру замены IP.
        Пул резервных IP: Gryphon заранее заказывает у провайдеров несколько свободных IP и держит их неназначенными.
        При аварии выбирает IP из пула, назначает его на хост (VPS) проблемного гейта через API провайдера или SSH-команды.
        Обновляет сетевую конфигурацию гейта (если требуется) и перезапускает необходимые сервисы (socat).
        После успешной замены обновляет config/gate_ips.json.
        Старый IP, если он был причиной сбоя (блокировка), освобождается через API провайдера, чтобы не платить за него.
    Ведёт учёт и предоставляет информацию.
        Хранит историю замен, текущий статус гейтов.
        Предоставляет HTTP-эндпоинт (localhost) для CLI-команд типа uadmin gryphon status или ручного запуска замены.

### Реализация ядра Gryphon
- [ ] `config.py` — загрузка параметров из .env (ключи провайдеров, SSH, настройки московского гейта)
- [ ] `gate_manager.py` — чтение/запись gates.json, ip_pool.json, блокировка гейта во время замены
- [ ] `monitor.py`:
- Цикл опроса гейтов (интервал 10-15 сек)
- Каскадная проверка через SSH с московского гейта:
  1. Легкая: `nc -zv -w 3 <target_ip> 443`
  2. Тяжёлая (при N=5 неудач): `curl --socks5 <moscow_gw>:1080 ... ifconfig.me` с проверкой ожидаемого IP
- Счётчик неудач для каждого гейта, сброс при успехе
- При достижении порога — вызов activator.replace(gate_id, old_ip)
- [ ] `activator.py`:
- Получить IP из пула (если пуст — запросить у провайдера)
- Назначить IP на хост (через SSH или API провайдера)
- Проверить доступность нового IP (аналогично монитору, но быстрее)
- Обновить gates.json, gate_ips.json (атомарно)
- Отправить алерт (через notifier)
- Освободить старый IP (опционально)
- [ ] `provider/aeza.py` — реализация методов allocate_ip, assign_ip_to_server, release_ip для Aeza.net
- [ ] `notifier.py` — вызов send_admin_alert (из cli.notify или напрямую через Telegram API)
- [ ] `api.py` — простой aiohttp HTTP на localhost:9xxx для внешних команд:
- GET /status — состояние всех гейтов
- POST /replace — принудительная замена (параметр gate_id)
- GET /pool — содержимое ip_pool.json
